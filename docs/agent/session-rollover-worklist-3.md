## 1. 授权（用户 2026-11-09）

用户授权用真实模型运行本对比，**预算不设上限**。据此：

- **模型**：
  1. 第 2 轮准备的 `openai-codex` / `gpt-5.6-luna` / thinking `low`；
  2. 用户日常默认模型：读 `~/.pi/agent/settings.json`（或 `$PI_CODING_AGENT_DIR/settings.json`）的默认 provider/model/thinking。若与 1 相同则只跑 1。若是 Qoder，费用按 Qoder 已记录的 credits 报告，规则同 CLAUDE.md 第 2 节。
- **把授权写进代码**：`ROLLOVER_LIVE_AUTHORIZATION` 改为按模型列出的授权记录（`id` 注明日期与“用户授权，预算不设上限”）。`maxRepetitions` 为 5。
- **请求与 token 上限仍保留**：它们是防止死循环和异常重试的保护，不是费用上限。按任务实际规模算出上限后取 2 倍写入。某组因触及上限而中断时，允许把该上限放大一次重跑这一组，并在回报中写明。
- **不授权**：发布、合入 `main`、改默认开关、改动用户正在使用的安装。
- **模型无法使用**（未登录、凭据过期、额度耗尽）：不代为登录、不读写凭据，跳过该模型继续其他工作，在回报中写明需要用户做什么。

## 2. 工作包

### W13. 补一个“没有提示该检索什么”的任务

现有任务的第二个提示直接点名 `EXACT_CODE`，等于告诉模型去检索什么，测不到 v2 设计第 9 节的主要风险：模型不知道早期约束存在。新增任务：

- **第 1 轮**：用户给出一条项目规则，只在这一轮出现。例如：“本项目新建的任何文件第一行必须是 `<随机 24 位标记>`；不要修改 `config/locked.json`。”模型回复确认即可。
- **第 2 轮**：要求读完清单里的文件（含 bulk 文件，使压缩发生在**这一轮中途**），然后新建 `notes/summary.md`，列出读过的文件。这一轮的提示**不重复、不暗示**第 1 轮规则。
- **核验**：新文件首行与标记逐字一致，`config/locked.json` 逐字节未改，其余 fixture 未改。

两组的任务、`compaction` 设置与切点参数完全相同，只切换 `ROTOM_SESSION_ROLLOVER`。

v2 会逐字带上**当前**这一轮的用户请求，所以第 1 轮的规则只能靠原生摘要保留，或靠模型主动检索。这正是要测的差异，不要为了让某一组通过而调整任务。

faux 干跑要覆盖两种结果：遵守规则判对、忽略规则判错。

### W14. 统计口径补充

`summaryShare` 现在以全部助手 usage（以 cacheRead 为主）为分母，会低估。另外输出两组比例：

- 摘要调用的 input 占全部助手**未命中缓存的 input**（`input` 字段）的比例；
- 摘要调用的 output 占全部助手 output 的比例。

补单测后在本机重跑，写进回报。仍只报 token，不换算费用。

### W15. 真实运行

- 每个授权模型 × 两个任务 × 两组 × 5 次重复。
- 每次记录：
  - 是否答对；
  - 请求数、input / output / cacheRead / cacheWrite；
  - 端到端时长；
  - Provider 报告的费用或 credits（没有就记 unknown）；
  - 本次发生了几次原生摘要、几次接管；
  - `context_recall` 的调用次数和查询词（查询词只记长度与是否命中，不记原文以外的内容）。
- 汇总表按“模型 × 任务 × 组”给出正确率、各项中位数与范围。两组差异只按实测陈述，不做显著性宣称，不用 token 推算费用。
- 每组运行之间不共享会话、缓存目录或工作区。原始逐次记录存到 `rotom/evals` 现有的结果目录约定下，不含凭据。

### W16. 核实第 2 轮记录的 Pi 取消问题

第 2 轮决策记录第 6 条提到：有 active Goal 时，如果“请求前的阈值压缩”被处理器取消，Pi 会反复重试同一个越线请求，测试一直不结束。这条路径在现状下也存在：Offload 推迟、Goal 预算取消都会取消压缩。

- 写一个最小复现测试，只用 Pi 与一个返回 `{ cancel: true }` 的测试扩展，分别覆盖有 Goal 和无 Goal 两种情况，确认是否会循环、循环到哪里为止（比如是否受重试预算限制）。
- **只复现和记录，不修**：修改 Pi 的取消语义需要用户决定。复现测试若会挂起，用超时把它标成已知缺陷（`todo` / `skip` 并写原因），不要让套件挂住。
- 在回报中写清：触发条件、实际行为、对用户的影响（Offload 默认开启时是否可能遇到）。
