# 第一次真实回放：操作步骤（bob）

目标：用几个真实的失败会话，确认回放从头到尾能跑通、判定结论讲得通。第一次只回放**当前版本**，不做新旧对比。

## 0. 准备（只做一次）

1. 在 `~/rotom-eval`（`eval/system` 的独立 worktree，不是日常会话在用的那份 checkout）执行 `git pull`。
2. 按 CI 的参数安装运行时：
   ```
   npm --prefix rotom/runtime/pi ci --ignore-scripts --bin-links=false
   npm --prefix rotom/extensions/third-party ci --ignore-scripts --omit=optional --legacy-peer-deps
   ```
3. 像之前试 judge 时那样，用这个 worktree 的 rotom 启动 `--trace`，打开后台的 Eval 页。截图时记得裁掉链接里的 token。

## 1. 标回放点（3 到 5 个）

1. 选你已经标为「不满意」或加入失败集的会话，优先选你记得问题出在哪一步的。
2. 在时间线上找到**出问题的那条 assistant 消息**，点「设为回放点」。回放会从这条消息之前开始，重新生成它。
3. 写一句期望行为，例如「应该先查状态再回答」。
4. 选判定方式：
   - 规则 `checks-before-claiming`：下一步应该先查，不该直接下结论；
   - 规则 `no-identical-retry`：不该原样重试刚失败的那次调用；
   - 规则 `nonempty-handoff`：不该空着回复，要交代进度或下一步；
   - 都不合适就选「模型判定」，它会照你写的期望行为来判断。

## 2. 运行

1. 在「回放集」里选中这几个点，模型填 `qoder/dfmodel`，重复次数填 1，**不勾选**「同时跑基线」。
2. 先看确认弹窗里的数字：总次数，以及截断前内容的总字符数和单个最大值。单个最大值超过约 30 万字符时，先取消，换一个更短的会话或更早的回放点。
3. 确认后等待跑完。每个点大约几十秒，可以随时取消。

## 3. 告诉我结果（只发汇总，不发会话内容）

请回我这几项，不要贴会话原文或截图里的对话内容：

- 每个回放点的判定方式和结果（通过、失败、unknown）。
- 对每个结果，你觉得判得对不对，一句话说明，例如「它这次先查了状态，判通过是对的」「它其实答对了，但规则没认出来」。
- 有没有报错，或者卡住的情况。
- 确认弹窗里的总字符数，以及运行用了多久，记个大概就行。

## 之后（可选）：新旧对比

想对比新旧版本时：

1. 另建一个 `origin/main` 的独立 worktree，按同样的参数装好运行时。
2. 启动后台前设置 `ROTOM_EVAL_REPLAY_BASELINE=<那个 worktree 的绝对路径>/rotom`。
3. 这时面板上会出现「同时跑基线」。如果提示「两臂产品摘要相同」，说明这次对比没有意义。
