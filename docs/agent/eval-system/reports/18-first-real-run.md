## 判定结果

三个点都判 `pass`。逐条复核认为都站得住：

- 两个规则点：新回复换成了不同的调用，没有原样重试刚失败的调用，规则判 `pass` 与事实一致。
- 一个模型判定点：新回复继续推进工作而不是以报错结束，与期望行为一致。

这一轮没有出现 `fail`，因此**还不能证明区分度**：这三点取的都是「模型本来就会恢复」的时刻。要证明判定能抓住退化，需要一次对照（同一批点用旧模型、或刻意选一条不成立的规则重判）。

## 本轮发现并修掉的问题

1. **会话路径假设错误（阻断）**：回放服务把会话当成 `<根>/<id>.jsonl`，真实会话是 `<根>/<project>/<时间戳>_<id>.jsonl`。改为由 Eval 服务解析真实路径（`pathOf`），服务把解析结果通过 `--paths` 传给运行器；运行器只接受已解析文件，不再自己拼路径。测试覆盖嵌套目录。
2. **8 MB 读取上限（阻断）**：真实会话 17 MB、22 MB，读取直接判 `oversized`，返回 `cannot_read_session`。改为 `REPLAY_SESSION_MAX_BYTES`（128 MB），与 Eval 页自身 256 MB 上限同一量级。测试用 ~9 MB 的会话验证。
3. **运行器不认识 `--paths`（阻断）**：第一次运行因此在 6 秒内失败，模型未调用、无费用。参数表补上并加回归测试。
4. **Pi 可执行文件解析（阻断）**：每臂加载产品时没有显式 `--pi` 就回退到 PATH 上的 `pi`（日常安装，identity 不符），直接抛错。改为：显式 `--pi` > `ROTOM_PI` > 该臂产品的 `runtime/resolve-installed-pi.mjs`。这一点也保证两臂各自用自己随附的 Pi fork，不会静默用同一份 Pi 做对比。测试断言隐式解析与显式解析得到同一 digest。

## 需 bob 决定

1. **「UI 没先出设计稿就盲改」那个点没跑**：该会话最早的文件改动回放点在 681k 字符，超过本轮 50 万上限；50 万以内只剩一个「以报错结束」的点，与原始问题不是同一件事。要么放宽到 70 万字符，要么接受这个点用别的会话/更早时刻。
2. **判定区分度**：是否安排一次对照（旧版本臂或旧模型），否则「3/3 pass」只能说明链路通，不能说明判定能抓住退化。

## 已知限制

- 单个条目特别大（实测 9 MB 的单条消息）会让 `redactSecrets` 抛 `RangeError: Maximum call stack size exceeded`，准备弹窗请求会 500。真实会话的单条消息一般远小于此，本轮三个点未触发；修法是分批脱敏或对超大条目降级计数。本轮未改，先记录。
- 运行记录的 `usage` 为 `null`：回放路径没有采集 token 用量，因此无法从结果里核对花了多少。
- 本轮只跑当前版本、单臂，`sameProduct` 恒为空；两臂摘要对比仍未在真实数据上验证。

## 核验：accepted（第一次真实回放 L2 通过）

本地复跑：node 测试 71 项通过；`replay-e2e` 5 项通过、0 项 skipped。

4 个阻断问题修得合理：
- 会话路径改由 Eval 服务解析，通过 `--paths` 传给运行器，运行器不再自己拼路径；
- 读取上限放宽到 128 MB；
- 补上了 `--paths` 参数；
- 每个臂用自己随附的 Pi fork，不再回退到 PATH 上的 `pi`。

第 4 条同时保证了两臂不会悄悄共用同一个 Pi。

### 两处已知限制，我补充一下原因

- **`RangeError` 的根因是 JWT 规则。** 我复现了：一个约 6 MB、以 `eyJ` 开头的长串（比如 base64 编码的 JSON 或图片数据），会让 `jwt` 规则 `\beyJ[A-Za-z0-9_-]{8,}\.…` 栈溢出。其余 8 条规则在同样的输入上都正常。后台 judge 也会对整段字段做脱敏，所以同样会受影响，不只是回放。修法：给各条规则的量词加上限（JWT 每段比如 `{8,4096}`，私钥块 `[\s\S]{0,8192}?`），并加一个约 9 MB 输入的回归测试。
- **`usage: null`。** 需要从回放的 assistant 消息或会话统计里取 token 用量，和 judge 的记录口径一致。

### 区分度

三个点都判通过，只能说明链路通了，不能证明判定抓得住问题，这一点报告写得对。

最便宜的对照不是旧版本或旧模型，而是**原始那条出错的回复**：bob 标为回放点的那条 assistant 消息，本身就是当初的错误示范。用同样的规则或模型判定给它打一次分：
- 如果原回复判**失败**、新回放判通过：说明判定抓得住，而且这个点上产品或模型确实有改进。
- 如果原回复也判**通过**：说明这个点选错了，或者判定抓不住这类错误。

这个对照不需要生成新回复（只有模型判定会花一次判定的钱），应该作为每次回放的默认第三臂「original」。
