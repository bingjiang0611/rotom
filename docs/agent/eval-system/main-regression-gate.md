# main 回归门禁

本文件是 `CLAUDE.md` 的强制执行合同。每次直接推送、PR 合并或其他方式更新远端 `main` 前，均须运行一次真实失败集回归；包括文档和发布元数据变更。功能分支推送不触发本门禁，也不能用来绕过后续 main 合入检查。

## 运行前

1. Fetch 后记录最新 `origin/main` SHA。基线产品必须来自该提交，不把任意已安装版本当成 main。候选产品必须来自最终待推送代码树；PR 合并须验证整合 main 后的结果。按产品既有流程准备两臂运行时，禁止覆盖活跃安装。
2. 读取已复核的本机冻结失败集，确认非空、无排除点、索引完整、来源与判定版本有效。首次可执行 `prepare --name=failures --selector=failSet`；已有集合不得为了通过而删除失败点或盲目 `--force`。新增或失效点需复核再冻结。集合留在 `~/.rotom/evals/replay/sets/`，不进入 Git。
3. 明确生成/判定模型、thinking 配置和重复次数（默认每点每臂一次）。用同一配置运行两臂，original 对照保留。没有指定模型时询问，不自行选择有费用的模型。
4. 从维护 checkout 调用命令。全局安装包不含此工具，不能使用它替代；调用方设置 `ROTOM_PI` 时按工具约束拒绝，不悄悄选择另一个运行时。

## 先计划，后真实运行

以下参数是占位符，须替换为本次确认值；在仓库根执行：

```bash
./rotom/bin/rotom eval-regression run \
  --set=failures \
  --baseline=<最新main构建的绝对产品目录> \
  --candidate=<最终候选构建的绝对产品目录> \
  --model=<provider/id>
```

未加 `--yes` 的命令只打印计划、不调用模型，退出 2 是预期行为，不算运行失败或通过。展示模型、两臂身份、用例数、生成/判定调用数、字符范围和隐私/成本边界。取得针对该计划的明确授权后，以相同参数追加 `--plan-digest=<打印的摘要> --yes` 运行一次。

- 没有计划授权则暂停 main 操作。不能从默认 Git 推送授权推断任意真实模型调用授权。
- 不自动重试失败、取消或 unknown 的调用，不重跑直到通过。有明确原因和修复后，才重新确认新批次。
- 只评分下一步决策，不执行回复中的工具。通过不代表原业务任务已完成，也不替代原有代码测试、构建和发布验证。

## 放行条件

必须同时满足：

- 本批次真实执行完毕且退出码为 **0**。
- 报告 `complete=true`，用例非空、覆盖完整；每点仅为 `stable-pass` 或 `improved`。
- `regression`、`still-failing`、`judge-blind`、`inconclusive`、`incomplete` 均为零。
- 报告的集合摘要、模型/配置、两臂身份及本地记录的 main SHA / 候选代码树与本次操作相符。报告自身不证明 Git SHA，须另行记录并核对。

退出 1 或 2、进程异常、报告缺失或任何证据无法核实，均不得推送/合并 main。即使问题在旧版已存在，`still-failing` 也不放行；不得自行改成“没有新增退化即可”。

## 推送/合并前再核对

- 再次 fetch：目标 main 已前移则重新整合、构建和运行；候选代码树、运行配置、冻结集合或受测产物发生变化同样使结果失效。
- 在本机报告旁保存本次 Git 来源、计划摘要、报告路径、退出码和放行结论。报告与私有会话、期望、标注、回放内容均不上传；公开交付只写必要的提交与通过/阻塞状态。
- 现有身份检查不是不可变执行快照，不覆盖所有已安装依赖内容或扩展导入图。维护者须保证两臂与依赖在本批次期间不变；不能证明受测产物与待合入结果一致时按阻塞处理。

这是 Agent 的行为门禁，尚未实现 GitHub required check 或分支保护；人工/外部客户端仍可能绕过。不得把 `evals-l1.yml` 的合成测试成功当成本门禁通过。要服务端强制拦截，需另行设计不上传私有内容的验证凭据与分支保护方案。
