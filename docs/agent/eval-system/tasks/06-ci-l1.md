## workflow 要求

- **触发**：`pull_request`，以及 push 到 `main` 和 `eval/system`；两者都加 `paths` 过滤：`rotom/evals/**`、`rotom/extensions/observability/**`、`.github/workflows/evals-l1.yml`。另加 `workflow_dispatch`。
- **权限**：顶层 `permissions: contents: read`，不申请其它权限。不使用 `pull_request_target`。
- **并发**：`concurrency` 按 workflow + ref 分组，`cancel-in-progress: true`。
- **job**：`ubuntu-latest`，`timeout-minutes: 15`。
- **actions 固定到 commit SHA**：`actions/checkout` 和 `actions/setup-node` 都用完整 SHA，后面注释写版本号；SHA 从官方仓库的 release tag 查到，报告里写出查证方式。checkout 设 `persist-credentials: false`。
- **Node**：24（和产品 `engines` 一致），开启 npm 缓存，缓存依赖路径为 `rotom/evals/package-lock.json`。
- **步骤**（`working-directory: rotom/evals`）：
  1. `npm ci --ignore-scripts --registry=https://registry.npmjs.org --replace-registry-host=always`
  2. `npm test -- session-cards trace-assertions agreement`（vitest 按文件名过滤；任务 04 还没合入时 `agreement` 匹配不到文件也不能报错，报告里写明实际匹配到哪些文件）
  3. `npm run typecheck`
  4. 在仓库根目录运行 `python3 scripts/audit-public.py --root .`
- 不上传任何 artifact，不打印环境变量，不读取 `~/.pi` 或 `~/.rotom`。

## 验证

1. 本地：`npx --yes @rhysd/actionlint@<固定版本>` 或者下载官方 actionlint 二进制检查 workflow，报告写出版本和结果。没法运行就写「未运行」，并说明原因。
2. 远端：推到 `eval/system` 后会自动触发一次 push 运行。报告写出运行链接、结论和各步骤耗时。失败就修到绿，每次修改单独提交。
3. 负向检查：在本地临时把一条 session-cards 断言改坏，确认上面第 2 步的测试命令会失败，然后**撤销这个改动**，不要提交。报告里写明做过。
