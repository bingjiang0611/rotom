# 前台接管改为“暂停 + 自动恢复”（第五期交接）

用户决定（2026-11-09）：前台接管（A6/F1，L4）运行期间，用户碰键鼠时**暂停**而不是结束;用户停手一小段时间后
在同一个接管上**自动恢复**,不需要用户再次授权或点任何东西。这替代当前“一碰即 `preempted_by_user`、需重新申请”的行为。

本文是给执行方的前向设计,不是对已推代码的审核。改完仍是代码 + 测试、不跑真机、先审后冻结。

## 绝不改变的安全不变量（暂停/恢复都必须满足）

这些是接管作为**同意层**的底线（根 `CLAUDE.md` §4),B 不得削弱其中任何一条:

1. **用户输入立即让出控制。** 任何未标记输入一出现,helper 立刻停止派发,光标与键盘焦点即刻归用户。
   这与现在的 preempt 行为在“让出”这一步完全一致,只是不再撤销租约。让出必须是即时的,不等任何确认。
2. **暂停期间零派发。** 暂停态下 agent 不投递任何鼠标/键盘事件,不移动光标,不抢前台。只有恢复后才继续。
3. **只信 helper 报告的真实输入。** 判定“用户是否在动”只认 `role=helper` 上报的未标记输入,agent 不能伪造空闲
   把自己恢复出来。
4. **用户随时能彻底结束,不只是暂停。** 保留一条明确的“结束”通道(菜单栏停止项、`Esc`/`Ctrl+Option+Cmd+.`):
   走这条就是硬结束(`released_by_user`),不再自动恢复,要继续必须重新走完整授权。日常碰一下键鼠是“暂停”,
   主动按停止是“结束”,两者区分开。

## 暂停态

- 触发:接管运行中出现未标记输入 → 进入 `paused`,原因 `user_input_pause`。立即让出(不变量 1、2)。
- 保留但不使用授权:前台许可(`foregroundGranted`)和 `desktop-foreground` 租约在暂停期间继续持有,
  但不派发任何事件。租约续租照常(否则会被当成放弃)。
- 边框:接管边框切到“已暂停”样式(例如灰色 + “已暂停,停手后继续”一行字),仍然点击穿透、不抢焦点、所有 Space 可见。
- trace:记一条 `{tool:"cu_session", status:"paused", evidence:"user_input_pause"}`(只记 id 与原因,不记输入内容)。

## 自动恢复的闸门(全部满足才恢复)

自动恢复本身是一次全局输入动作,所以它必须过和其它全局输入同样的闸门,再加几条接管专有的:

1. **安静期。** helper 报告最近一段时间没有未标记输入。复用 `requireQuietGlobalInput`(REVIEW-13 V2)。
   **安静时长待定(Q):** V2 对全局输入要求 30 秒;用户这里说“几秒”。两者有张力。默认先用与 V2 相同的时长(30 秒安静),
   不单独为恢复放宽;若要做到“几秒即恢复”,属于对安全闸门的显式放宽,必须单列理由,并且只允许在“本次接管自己被用户暂停后”
   这一受限情形放宽,不改其它路径。先按 30 秒实现,放宽与否等 Q 的决定。
2. **授权仍然有效。** 前台许可仍在、`desktop-foreground` 租约仍由本 agent 持有(或可无冲突续得)、目标 App/窗口仍存在。
   任一不成立 → 不恢复,转为硬结束,要求重新授权。
3. **暂停未超时。** 暂停超过上限(建议 2 分钟,设为命名常量)仍无法恢复 → 硬结束(`resume_timeout`),不再自动恢复。
   防止一个“僵尸接管”在很久以后毫无征兆地自己动起来。
4. **恢复次数与总时长有界。** 单次接管的自动恢复次数设上限(建议若干次),接管总时长设预算;达到上限 → 硬结束,
   要求重新授权。

恢复时:边框切回“活动”样式,trace 记 `{tool:"cu_session", status:"resumed", evidence:"auto_resume"}`。

## 模型侧与接口

- `cu_session` 的动作保持 `takeover` / `release_takeover`。`release_takeover` 是硬结束。不新增模型可调用的“恢复”动作——
  恢复由 helper/broker 在满足上述闸门时自动进行,模型不能自行把自己恢复出来。
- 暂停/恢复的状态转换全部在 broker + helper 判定(与 takeoverRefusal 同一处),模型侧只收到状态事件。

## B5 真机测试(前台接管)相应改为

原验收是“真实输入 → `preempted_by_user`、前台恢复”。改为验证暂停/恢复语义,仍需用户在场、约 30 秒配合:

1. 接管开始,边框出现(活动态)。
2. 用户发一次真实输入 → 立即让出,进入暂停态,边框变“已暂停”,期间 helper 观察到 agent 零派发。
3. 用户停手满安静期 → 自动恢复,边框回活动态,agent 继续。无需用户再授权。
4. 用户按 `Esc`/菜单栏停止 → 硬结束,不自动恢复;之后要继续必须重新授权。
5. 暂停超时 / 恢复次数用尽 → 硬结束。

B5 的全局输入动作前,仍按 REVIEW-13 V2 要求先过安静闸门。

## 给执行方的顺序

1. 暂停态(让出、零派发、边框、trace、保留授权与续租)。
2. 自动恢复闸门(安静期、授权有效、暂停超时、次数/总时长上界),全部在 broker/helper 判定。
3. 硬结束通道(`Esc`/菜单栏/`release_takeover`/超时/次数用尽)与自动恢复互斥、语义清晰。
4. 单元测试覆盖:暂停即让出且零派发、安静不足不恢复、授权失效不恢复转硬结束、暂停超时硬结束、
   次数用尽硬结束、agent 伪造空闲不能自恢复、硬结束后需重新授权。dry run 覆盖状态机。
5. 只做代码和测试,不跑真机。推送后报告 SHA,先审后冻结。
