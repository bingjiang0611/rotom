# Computer Use v2.1 B 阶段改在测试机上运行（第三期交接）

用户选择了方案 A：B 阶段不再占用用户正在使用的 Mac，改在一台专用测试机上跑。首选是这台 Mac 上的 macOS 虚拟机，
其次是一台闲置的 Mac。本文是执行方的操作约定；REVIEW-6 到 REVIEW-9 的规则继续有效，下面只写调整的部分。

## 为什么这样做

- 用户不用再离开电脑：测试机里没有人操作，门禁天然安静。
- 顺便回答 REVIEW-9 的 X2：虚拟机是干净系统，没有用户机器上的其他软件。如果 fixture 窗口出现时虚拟机里没有那段
  `pid 0 / state 1` 突发，就说明它来自用户机器上的某个程序，不是我们的激活路径。

## 第 0 步：只读检查（在用户的 Mac 上，不需要窗口）

REVIEW-9 X2 的只读检查照做：`hidutil list`、`ioreg -r -c IOHIDUserDevice -l`，以及拥有辅助功能、输入监控权限并正在
运行的程序。不启动、不操作任何 App。结果直接贴给用户和审核者，不提交进仓库。

## 第 1 步：方案（只写方案，不安装任何东西）

在 STATUS-2 里写一份测试机方案，交给用户批准。至少包括：

1. **虚拟化工具**：基于 Apple Virtualization.framework 的工具（例如 UTM 或 tart），说明怎么安装（例如 Homebrew）。
   系统镜像只用 Apple 官方的 IPSW，不用第三方预装镜像。
2. **系统版本**：虚拟机的 macOS 版本和用户的 Mac 一致；做不到时写明差多少，以及哪些结论因此不能外推。
3. **资源**：磁盘、内存、CPU 占用，以及虚拟机不用时怎么关掉、怎么整个删掉。
4. **执行方怎么在虚拟机里跑命令**：例如在虚拟机里开启“远程登录”，从宿主用 SSH 进去。helper 和 fixture 必须跑在
   虚拟机的图形会话里（自动登录一个专用测试账户），写清楚从 SSH 怎么把它们启动到那个会话。
5. **代码怎么进虚拟机**：虚拟机里有自己的 git checkout，`--expect-commit` 照常检查；`--runs-dir` 在虚拟机里，
   存档事后复制回宿主。
6. **签名**：先试 ad-hoc 签名（干净系统一般允许本机构建的 ad-hoc App）。**不要**把用户的 Apple Development
   证书或私钥导出到虚拟机；如果 ad-hoc 不行，停下来问用户。
7. **需要用户亲自做的事**：一次性的系统设置向导、在虚拟机的系统设置里给 helper 授权辅助功能和屏幕录制、
   设置测试账户密码。列成清单，并估计每项要多久。
8. **公司设备**：用户的 Mac 装有企业安全软件，在上面跑虚拟机可能触发告警或违反 IT 规定。方案里要写明，由用户确认。

用户批准之前，不安装任何软件、不下载镜像、不创建虚拟机。

## 第 2 步：搭建与冒烟（用户批准后）

搭好之后先做冒烟检查，不跑任何 B 步骤：

- helper `diagnostics`：协议号正确，`accessibility=true`，`screenRecording=true`；
- `build-fixture.mjs` 在虚拟机里构建成功，`minos` 回读正确，`source.sha256` 写入；
- 用 `PI_CU_LIVE=1` 只启动一次 fixture 副本、确认出现窗口、然后退出（这是一次 App 操作，只在虚拟机里做）。

## 第 3 步：在测试机上跑 B 阶段

规则调整：

| 规则 | 在用户的 Mac 上 | 在测试机上 |
| --- | --- | --- |
| 什么时候能跑 | 用户离开、授权一个时间窗口 | 用户授权某个冻结提交和某一步，不需要离开 |
| 门禁空闲时间 | 10 分钟 | 2 分钟（`--require-idle-minutes 2`），测试机里本来就没人 |
| 冻结、`B-STOPPED`、顺序 | 照旧 | 照旧 |
| 冻结前审核 | B1 及以后必须先审 | 照旧 |
| `PI_CU_FAKE_BACKEND` | 禁止 | 禁止 |

运行时不要在宿主上把焦点放进虚拟机窗口：键鼠进入虚拟机会被算作真实输入。

顺序：

1. **B0 对照**：用当前已审核的冻结提交，在虚拟机里跑一次 B0。看 fixture 窗口出现时有没有突发。
   - 没有突发：突发来自用户机器上的程序。REVIEW-9 X1 的三组实验不用做了，X2 由用户在自己机器上继续查。
   - 有突发：说明和用户机器无关，再做 X1 的三组实验（在虚拟机里做）。
2. 之后按 B1 → B2 → B3-live → B3-acceptance → B4 → B5 → B6，每一步的冻结提交都先经过审核。
3. **B5（前台接管）和 B6（`--with-hid`）** 涉及全局 HID，虚拟机里的 HID 是虚拟设备，结论可能和真机不同。
   这两步在虚拟机里通过后，审核者再决定是否需要在用户的 Mac 上补跑。

## 暂缓

REVIEW-9 的 X1（fixture“出窗口但不激活”模式）先不写代码，等 B0 对照的结果再决定。
