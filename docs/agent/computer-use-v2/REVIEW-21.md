## 接受的部分

### O1：打开目标分级

- **识别**（原生 `OpenTarget.inspect`）：读取目标的 `AXURL`，解析符号链接；只有“是文件 URL、是目录、原始和解析后都不是程序包、扩展名不是 `.app`”才算
  `directory`；普通文件算 `file`，程序包算 `package`，其他一律 `unknown`。跨进程只传 URL 加类型的 SHA-256 指纹，不传路径。
- **授权**：`requiresOpenConfirmation` 对 `directory` 以外的目标（含 `unknown`）都要求确认；`PolicyGate` 对外部打开设置
  `requiresFreshApproval`，broker 不复用会话授权、不写“总是允许”，新增“仅允许一次”；确认文案提示可能切到前台。没有 broker 时，外部打开直接拒绝，
  不派发。
- **执行前复核**（原生 `act`）：重新识别目标，类型或指纹与预检不一致就以 `open_target_changed` 拒绝；非目录且没有授权标记就以
  `open_confirmation_required` 拒绝。两种情况都不发出 AXOpen。
- 局限（符合根 `CLAUDE.md` 的协作式边界，不阻断）：`openApproved` 是我们自己的客户端声明的，helper 不能独立证明 broker 已批准；它防的是我们自己的客户端出错，
  不防同一用户下的其他进程。

## 系统权限弹窗

执行方查明弹窗内容是“绕过系统的窗口选择器，直接访问屏幕和音频”。helper 截图用的是 ScreenCaptureKit（`SCScreenshotManager`、`SCShareableContent`）。
在较新的 macOS 上，不经过系统内容共享选择器直接截屏的 App 会周期性收到这个确认（大约每月一次，新安装或新构建的 App 第一次截图时也会出现）。
普通 App 无法关闭它，Apple 只为远程桌面一类应用单独发放豁免。这不是缺陷，也不能绕过。

能做的：

1. 产品文档和首次使用说明里写明这个弹窗，以及选“允许”后大约一个月内不再出现。
2. 继续坚持 AX 优先：能用辅助功能读取时就不截图（`includeImage` 只在需要时开启），减少截图次数。不为躲避这个弹窗改截图方式。
