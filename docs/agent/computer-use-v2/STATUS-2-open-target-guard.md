## O1

- 事务授权前，使用当前观察的 wire ref 读取 AXURL，并读取原 URL 与解析符号链接后的文件类型。只有可确认的非程序包目录免于**额外的打开目标确认**；普通 click 级 App 授权仍保留。
- 文件、脚本、程序包、缺 URL、非文件 URL、类型读取失败均须新确认。程序包检查覆盖原始路径和链接目标，不能用 `.app` 链接绕过。
- 确认卡保留已有警告，并写明“会用其他程序打开，可能切到前台。”仅提供本次允许和拒绝。会话授权、始终允许和关闭普通敏感词检查均不能跳过这次确认；本次允许不生成可复用授权。
- 批次中的打开目标先全部检查，再请求租约和授权。拒绝时不进入派发回调，连批次前缀也不派发。broker 关闭或不可用时，外部/未知目标不降级成本地直接写。
- 原生派发前再次读取类型，核对 URL/类型摘要及本次确认标记；缺少预检、目标变化或失效 ref 均拒绝。不重找目标、不尝试替代动作。通过检查后仍只调用一次 AXOpen，结果保留 unknown，等待只读效果核验。
- helper 协议 `10 → 11`，broker 协议 `1 → 2`。旧进程不会被自动升级或重启。摘要不携带原始文件路径；确认标记是本地合作式调用合同，不是 OS 沙箱或对任意本机客户端的安全保证。
- broker 的隔离源码目录同步包含 `open-target.ts` 与 `constants/copy.ts`，避免源码单测通过而安装路径的 daemon 无法启动。

## S2

- `pretest` 改为 `typecheck:fatal`。仍运行完整 strict/noEmit TypeScript 程序并打印全部诊断，不增加 any、忽略指令或排除源码。
- 临时阻断名字/模块/导出不存在、不可调用/构造、初始化前使用，以及 `src/`、`extensions/` 内属性不存在等类别；语法/配置错误、编译器启动失败、异常退出和截断错误也阻断。具体集合在脚本中显式维护；这不是完整运行时安全证明。
- `npm run typecheck` 保留原合同：当前仍非零退出，144 项类型债务。基线为 146 项；仅按 REVIEW-17 将 `statSafe` 返回值改为 `Stats | undefined`，消除两项 number/bigint 推断错误，其余另轮处理。
- 默认文件级并发两次出现子进程启动超时；改为 `--test-concurrency=1` 后完整 `npm test` 通过。未放宽任何超时或删减断言，测试内部的多进程并发场景仍保留。资源争用是推断，不声称查明了系统层根因。

## 权限弹窗只读取证

用户提供的措辞指向绕过系统私有窗口选择器的直接屏幕／系统音频捕获权限，不是 Accessibility，也不是 Ask 的 App 操作授权。措辞本身不证明麦克风访问或实际录音。

限定时间范围的系统日志未找到匹配归因记录，系统 TCC 数据库拒绝读取。已核实测试 helper 的进程与签名身份，但**不能据此确定弹窗请求 PID**；旧测试显示名只可能是身份缓存，不是已证实原因。测试启动时的 permissions 读数早于弹窗，不能证明后来 Allow 的结果。本轮没有为取证复现捕获、改权限、重启或改 App 名称。

## 后续边界

先审核提交，再由维护者另行授权冻结和独立重建；本轮源码尚未安装、未更新 vendor 归档，也没有 O1 真机证据。精确弹窗归因仍需用户提供该时段可读的 TCC 请求/责任进程记录，不自动申请额外权限或复现系统弹窗。
