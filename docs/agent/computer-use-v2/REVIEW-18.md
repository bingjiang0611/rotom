## 审核要点

- **期限对齐**：客户端普通请求 45 秒，而 broker 的授权期限是 120 秒，客户端会先放弃。现在只有 `acquire` 额外加上授权期限（165 秒），
  需要排队时再加排队期限（195 秒）；不自动重发，不新增配置。负对照：恢复旧的 45 秒，新回归失败。
- **迟到授权一定被拒**：broker 收到决定时按实际截止时间再判一次，即使定时器还没触发也拒绝；迟到的“总是允许”不写入策略。
  UI 侧的选择框用 broker 截止时间和连接的取消信号限时；过期、断线、没有 UI、界面出错，一律按拒绝处理。
- **异常回执带回请求 id**：`server.ts` 捕获异常后回显原请求 id，调用方能立即收到失败，而不是等到超时。
- **报错文案**：只有真正的 `resource_busy` 才报告持有者；`broker_unavailable` 明确说不能证明有别的 agent 占用，要求停下查诊断，
  不自动重试、不停止其他会话、不关闭仲裁。租约失败标记 `dispatch=not_started`；原本是 unknown 或部分执行的结果仍保持 unknown，不会被改写后重放。
- **诊断**：只记录请求 id、阶段（received、prompt_requested、decision、unavailable、expired、cancelled、ui_error、response_ack、response_error）
  和决定枚举；不记录 App、窗口、标签、卡片文字或错误正文；沿用已有 trace 的关闭开关、私有权限和保留上限。`prompt_requested` 只证明调用了 UI 接口，
  不证明用户看到了卡片，记录里如实写明。
- 没有改 broker wire 版本、helper 协议、原生代码或发行归档。
