## 本次变化

Computer Use helper 的自动同步失败不再阻断 `rotom` 启动。

此前每次正常启动先跑一次强制 helper 同步，同步抛错即整个产品退出（退出码 1），会话从未开始。触发条件是“已装 helper 由某个证书签名、而该证书已不在 keychain”：更新器要求恰有一个可用身份来重签，取不到就拒绝。Computer Use 因此从可选能力变成了启动门禁。

现在同步失败只在 stderr 报两行：原始 helper 错误，加上一条说明 Computer Use 保留旧 helper、本会话继续，并给出两条真正可用的出路（指定 `PI_COMPUTER_USE_CODESIGN_IDENTITY`，或显式运行 `PI_COMPUTER_USE_ALLOW_ADHOC_UPDATE=1 rotom helper update`）。

替换策略本身没有放宽：自动同步仍然不会把证书签名的 helper 降级成 ad-hoc，不停旧 helper，不重放未知写入；`PI_COMPUTER_USE_ALLOW_ADHOC_UPDATE=1` 在自动同步里依然无效，提示里明确写了这一点。原生 helper、broker 协议和全部 8 个预构建文件未变。

## 验证边界

新增的隔离 HOME 启动回归（外来 update-lock 强制同步失败）在修复后通过：退出码 0、stdout 只有 JSON、stderr 同时含错误与引导、已装 helper 字节不变、外来 lock 保留。撤回 launcher 改动后该用例失败，说明它确实能区分两种行为。产品发行门 39/39、更新器套件 15/15、组件 helper-update 套件 25/25 通过。

本次没有真实桌面写入、真实 Provider、浏览器/手机或跨平台验收；这些不因发布而改变。测试机上的现场（macOS 26.3.2，0.2.2→0.2.3）通过手工 `PI_COMPUTER_USE_ALLOW_ADHOC_UPDATE=1 rotom helper update` 恢复，该现场不构成 0.2.4 启动门禁的真机验证。
