## 审核后的执行顺序

按 [npm 正式发布顺序](../agent/contracts/npm-release.md) 和 [验证与交付](../agent/verification.md) 执行：

1. **先审核冻结提交。** 审核通过前不构建。通过后只在该冻结 commit、干净工作区执行一次 `npm run pack:release -- /absolute/output-dir`（在 `rotom/` 下）。隔离 HOME/cache，只继承标准代理路由；不读取用户全局 npmrc，不并发重度任务。该次失败或结果未知时先停止并交接，不自动执行第二次。
2. **验证实际最终 tgz。** 记录文件数、大小、SHA-256/SRI，并审计实际 tgz；在隔离 HOME 和 prefix、PATH 无全局 Pi 的环境安装，运行版本、default/full smoke、check-personal、升级与卸载检查。源码、组件 tgz 或历史结果不能替代最终产品产物。
3. **新增受管 Mac 硬门禁。** 从最终 tgz 的隔离安装调用 `rotom helper update`，使用用户已有的 **Apple Development** 身份，只签署并安装到隔离 HOME 中的 helper 路径。运行前核对 app、socket/broker 路径都隔离，不连接日常 helper；身份不明确时先询问用户，不创建证书、不导出私钥。如果隔离 HOME 下 `codesign` 找不到身份，立即停止并报告，由用户决定下一步；不复制钥匙串、不改钥匙串搜索列表、不导出私钥。
4. **真实启动与回读。** 启动该隔离安装的 helper，读取真实 diagnostics，要求 `protocolVersion === 11`，并核对 PID 和可执行文件路径确属本次隔离副本。签名验证通过不能代替启动证据。测试结束只关闭本次创建的实例；确认该实例已退出并保存证据后，删除本次创建的隔离 HOME（包括隔离 helper 副本）。最终 tgz 必须存放在该 HOME 之外，保留到发布与 registry 核验完成。不停止、覆盖、迁移或重启日常 helper。
5. **被端点安全终止就停止发布并报告。** 不更换路径/身份、关闭安全控制、重置 TCC、降低门禁或反复启动来绕过拒绝。没有成功证据即不进入发布。真实“停止日常旧 helper 再升级”仍需用户另行授权。
6. **认证与发布交给用户。** 全部 artifact 验证通过后，用 `node scripts/npm-release-handoff.mjs commands <absolute-final-tgz> latest` 生成分阶段精确命令，逐段交接。Agent 不执行 `npm login`、`npm whoami` 或 `npm publish`，不启动认证浏览器，不接触密码、OTP 或 token。
7. **公开状态只读核验。** 用户前台执行后，由 helper 的 verify 和 registry 查询核对 version/tag/integrity/shasum/tarball 字节。submitted 或 npm 自动审核不代表已发布，不重复 publish；只有 verified 后才记录正式发布、创建 tag，并另行交接本机切换。

当前只等待**冻结提交审核**。上述打包、隔离原生启动、最终产物安装和 npm 步骤均未执行，不把计划写成验收结果。
