# Agent regression

这是仓库维护 skill，不进入产品 bundle。先确认 Git 根、当前 diff 和用户要做的是入集还是运行；两者都要时先入集。[操作合同与命令](../../../docs/agent/agent-regression.md)是唯一详细入口。

## 新失败入集

1. 查原始证据，分清目标、实际结果和基础设施错误；证据不足标 `unknown`，不编造失败标签。
2. 提取最小场景并脱敏。保留导致失败的区别；真实会话、截图、凭据和运行结果不进入公开 Git。
3. 复用最接近的 suite/harness。把验收写在模型不可见的 judge 中；加入已观察错误的反例和至少一个正确控制。没有可验证 oracle 时只记录待确认项，不自动纳入通过率。
4. 跑受影响的离线测试。报告用例 ID、来源范围、脱敏变化、验收和反例证据。不要仅追加一条 prompt 就宣布入集完成。

## 修改后回归

1. 按 diff 和失败机制选集，先跑离线检查。不把普通提交视为付费模型授权。
2. 确认模型、发送数据、重复数和预算授权；固定两个产品根、同一输入/judge/工具/模型。不得用另一模型的旧结果冒充本次基线。
3. 按操作合同运行，检查实际样本数及逐例证据；跳过、超时和 provider 错误不是通过。外部写入 unknown 不重放。
4. 分列新退化、改善、原有失败、unknown，以及 token/耗时/估算费用。Judge 分数不是业务成功；不能把 A/A 冒充改动收益。

交付：变更文件与用例 ID、实际验证、未验证范围、私有结果路径、commit/push 状态。Jev 可辅助分流，但置信度不能替代事实验收。
